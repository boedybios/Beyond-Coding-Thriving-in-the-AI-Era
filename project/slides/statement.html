The one rule to remember

Never submit code
you can’t explain.

Not to your lecturer, not to your team, and never to production.

(~1 min) Pause here and let it land. This is the one rule to remember from today. If you can’t explain how a piece of code works, you can’t debug it, defend it in a review, or take responsibility when it fails. In class, explaining your code is how lecturers check what you learned. At work, “the AI wrote it” is never an acceptable excuse for a bug or a security incident.
