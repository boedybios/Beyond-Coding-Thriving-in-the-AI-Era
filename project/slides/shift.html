01 · What’s changing

What AI speeds up, and what stays with you

AI speeds up

  • Typing boilerplate and repetitive code
  • Recalling syntax and library APIs
  • First drafts of code, tests, and docs
  • Explaining code you haven’t seen before

Still on you

  • Understanding the real problem
  • Choosing the approach and trade-offs
  • Judging whether the result is correct
  • Owning what ships, and its consequences

The faster code gets written, the more your judgment matters.

(~3 min) This is the core idea of the talk. Left: the mechanical parts of programming, like typing boilerplate, remembering syntax, and writing first drafts, are getting much faster. Right: the parts that need understanding and judgment. AI can help here too, for example by suggesting approaches, but it can’t be accountable, and it doesn’t know your users or constraints unless you tell it. Example: your lecturer asks for a library management system. AI can generate the basic create, read, update, and delete code in minutes. But who are the users? What happens when a book is lost? Which data must stay private? Those answers decide whether the system is actually useful. Ask the room: which column has most of your coursework trained so far?
